## 1. 现状要点（2026-10-30 盘点）

- 页面层 `lib/pages` 共 55,206 行，`lib/widgets` 约 10 万行，约 230 个界面。
- 改动面：`colorScheme.` 2179 处 / 254 个文件，`textTheme.` 891 / 198，`fontSize:` 376 / 130，`BorderRadius.circular(` 619 / 201。图标方面，`Symbols.` lib 1510 处 + packages 243 处，`Icons.` 283 处，`AppIcons.` 只有 31 处。
- 硬编码颜色：lib 里 `Color(0x` 220 处，`Colors.` 655 处（其中 177 处是 `Colors.transparent`）；ai_model_manager 里 `Color(0x` 69 处，`Colors.` 33 处。
- 共用外壳的调用量：
  - `showAppDialog` 92、`AlertDialog(` 96、`showAppBottomSheet` 58、`AppSheetScaffold` 29、`ToastService.` 359；
  - `SegmentedCardGroup` 41、`SwipeDismissiblePopupMenu*` 31、`ErrorView` 22；
  - 骨架组件 7 个文件，另有 59 处使用；`LoadingSpinner` 84。
  - **这些外壳是最大的抓手**：在原处换皮，大多数页面不用改调用点就变成 v2 样子（M2）。
- 第 1 期 iOS 适配层（469ab668）：
  - `lib/theme/design_tokens.dart`（667 行，`AppDesignTokens` ThemeExtension）+ `lib/theme/app_adaptive_theme.dart`（100 行）+ `SegmentedCardGroupStyle` + `AppSheetShellStyle`，配 3 个测试文件。
  - **页面里一处都没用 `AppDesignTokens.of`**。颜色全部从 ColorScheme 派生，没有固定值；字阶是 iOS HIG 的 10 档；只在 iOS 生效。
- 渲染器 `packages/fluxdo_render` 是 **git 子模块，指向上游 `Lingyan000/fluxdo_render`**，我们推不上去。
  - 本 worktree 里子模块没初始化（目录是空的）。
  - 它对外只有 `baseTextStyle` 一个样式参数，另有 `selectionEnabled` 开关和一组 builder 覆盖。
  - 颜色全部取自 `Theme.of(context).colorScheme`：引用块是 `surfaceContainerHighest`@0.3 底加 4px `outline` 左线，代码块是 `surfaceContainerHighest`@0.5，链接是 `primary`，表格线是 `outlineVariant`。
- 阅读页：
  - `TopicPostList` 是带 `center:` 的 `CustomScrollView`。
  - 楼层是 `PostItem`，长帖拆成三段。
  - 底部是悬浮进度胶囊 + 80 高底栏 + 回复 FAB，外加「进度条手势」。
  - 跳楼层用的是 `AlertDialog`。
  - 长按正文现在只能选字（渲染器自带的选字层）。
  - 楼层的「⋯」打开一个底部弹层，头像长按是径向菜单。
- AI 总结：
  - 话题头里已有服务端 Discourse-AI 总结卡（`CollapsibleTopicSummary`，看 `detail.summarizable`）。
  - 话题 ⋮ 菜单里有本地模型的全文总结半屏（`showAiTopicSummarySheet`）。
  - 设计稿里的「局部总结、要点 + 楼层链接」是新功能。
- 笔记：`TopicNoteStore`，SharedPreferences 键 `topic_notes_v1`，**按话题存**。
- 布局：
  - `Responsive.getDeviceType` 按**宽度**分档，600 以上算平板。6.9″ iPhone 横屏宽 956，所以现在会进侧栏，甚至双栏。
  - 帖子列表在非手机宽度下限宽 800。
- 主框架：
  - Tab 由 `NavEntryRegistry` 定义。通知是 `panel` 类型，点了打开 80% 高的快捷面板，**不是页面 Tab**。
  - 首页有分类抽屉、按分类左右横滑的 `TabBarView`、FAB、随滚动隐藏的底栏。
- 文案走 slang，ARB 在 `lib/l10n/modules/*/` 下，有 zh / zh_HK / zh_TW / en 四种；另有 102 处硬编码中文。
- 出包：
  - `ios-unsigned.yaml` 只能手动触发，版本号取 pubspec，build 号格式 `yyyyMMddHH`。
  - 关于页**只显示版本号，不显示 build 号**。

## 2. 实现前定下的决定

下面这些风险低，我已经按 A/B/C 选好；你不同意的话直接改。

| # | 问题 | 选定 | 理由 |
| --- | --- | --- | --- |
| P1 | 第 1 期适配层怎么处理 | **骨架沿用，取值换成 v2，搬进 `packages/common_ui`**。<br>沿用：ThemeExtension 注册方式、light / dark 对称装配、可比较（避免空跑主题动画）、`SegmentedCardGroupStyle` / `AppSheetShellStyle` 扩展点、对比度工具。<br>换掉：10 档字阶 → 4 档；从 ColorScheme 派生 → 固定 11 色；圆角 / 间距 / 材质取值；只在 iOS 生效的开关。<br>对照见 §3.7 | 机制已经过测试验证，值是错的。ai_model_manager 包只依赖 common_ui / m3e_ui / app_icons，所以 token 和组件放 common_ui，它才能用 |

## 7. 横屏规则（`layout/readable-max-width` 640）

- 手机和宽屏的判定：短边 < 600 是手机（P3），两个方向都用同一套手机布局。竖屏锁定的偏好保留。
- `readableInsets(context)`：
  - 可用宽 W = 屏宽 − 左右安全区；
  - W ≥ 640 时，左右内边距 = max(安全区, (屏宽 − 640) / 2)；否则内边距就是安全区；
  - 列内再留 20（设计说明 §5.6：列宽 640 含列内 20，正文行宽 600）。
- 落地方式：
  - 滚动内容：`SliverReadable`（SliverPadding）或 `ReadableColumn`（Center + ConstrainedBox）；
  - 导航栏、底部工具栏、Tab 胶囊、搜索胶囊：**底色铺满整宽，控件按 `readableInsets` 对齐阅读列**；
  - 半屏：宽 = min(640, 屏宽)，居中；
  - 对话框固定宽 320。
- 安全区一律从 `MediaQuery.padding` / `viewPadding` 取，不写死 62 / 21。
- 表格、AI 卡片、引用块都在列内，宽度跟着列走。表格的首列固定在 0.4.0 不做（P4），保留现在的横向滚动。
- 状态栏：iPhone 横屏系统自己会隐藏，不额外处理。
- 所有页面都用这条规则，不另做横屏设计。M3（首页、列表）、M4（阅读页）各自落地，M6–M9 换页面时顺带套上。
- 测试：956×440，左右安全区 62、底部 21，浅色和深色各一张；阅读页、首页、设置首页各出一张图。另测一个 W < 640 的尺寸（852×393，安全区 59）：阅读列应占满安全区内的全宽。

## 8. 动态字体（Dynamic Type）

- 原则：所有文字跟系统字号走（设计说明 §1-7），外观里的字号档和系统字号相乘。
- 全局：`MediaQuery.textScaler` = 系统 scaler × 字号档（0.88 / 1 / 1.12 / 1.24）。用一个自定义 `TextScaler` 实现，结果夹在 0.8–3.2 之间。
- 行高用比例（§3.3 的 `height`），字号变了行高跟着变。
- 高度只设最小值：列表行（72 / 96）、分组行 48、头像行等都是最小高，字变大就撑高，不截断（标题最多 2 行加省略号，这是设计规定）。
- 「框架」类控件有封顶，和 iOS 系统 Tab 栏的做法一样：浮动 Tab 胶囊、搜索胶囊占位、导航栏标题、工具栏、楼层胶囊、分类条、筛选胶囊，在组件里用 `MediaQuery.withClampedTextScaling(maxScaleFactor: 1.3)`。正文、列表、设置、半屏内容不封顶。
- 去掉现在零散的封顶：`search_page.dart:856` 和 `search_capsule.dart` 现在是 1.2，统一改成框架类 1.3。
- 字母头像里的字母不随字号缩放（它是图形，不是正文）。
- 测试：每页出 1.0、1.3、2.0 三档的图，并断言不溢出。2.0 那一档还要断言框架控件高度不变、内容行撑高。
- 真机：系统「更大字体」开到最大（含辅助功能大字），走查首页、阅读页、设置。

## 9. VoiceOver

- `AppIconButton` 必须传 `semanticLabel`（编译期强制），所有图标按钮都走它。审计脚本统计页面里裸的 `IconButton(`，M10 清零。
- 列表行：用 `MergeSemantics` 合并朗读，顺序是「标题，分类，作者，时间，N 条新回复，N 赞，N 回复」。左滑的「书签」「标为已读」和长按菜单注册成 `customSemanticsActions`，VoiceOver 转子里能选到。
- 通知行：开头先读「未读」或「已读」（设计说明 §1-7）。未读点本身不朗读。
- 楼层：
  - 头行合并朗读成「张三，楼主，#12，3 天前」；
  - 点赞按钮读「赞，16，已赞 / 未赞」；
  - 长按菜单的每一项都注册成这一层的自定义操作，VoiceOver 用户不需要长按。
- 楼层跳转时间轴：`Semantics(slider)`，值是「第 n 楼，共 N 楼」，上下轻扫 ±1 楼（`onIncrease` / `onDecrease`）。输入框标签是「输入楼层号，1 到 N」。
- 半屏和对话框：`scopesRoute` + `namesRoute`（用标题命名），关闭按钮读「关闭」，打开后焦点落在标题上。
- Toast：出现时用 `SemanticsService` 播报，不抢焦点。
- 等待提示和原地错误：用 liveRegion 播报。
- 分类条和页内筛选：每项是 `selected` 状态的按钮。
- 装饰性的东西（字母头像、发丝线、未读点）用 `ExcludeSemantics`。
- 测试：
  - 每个页面的 widget 测试都过 `iOSTapTargetGuideline`、`labeledTapTargetGuideline`、`textContrastGuideline`；
  - 关键行用 `matchesSemantics` 断言朗读文本和自定义操作。
- 真机走查路线：首页 → 打开话题 → 跳到某楼 → 对某楼用转子执行「回复这层」→ 关闭编辑器 → 通知 Tab。

## 11. 出包流程与版本号

1. pubspec 的 `version: 0.4.0+yyyyMMddHH` 每次出包都换新值；同一小时内出第二个包就 +1。**两个包绝不用同一个 build 号**（D-019）。
2. 提交后**先问你**，同意了才 push 本分支。
3. 带私有功能出包时，先把本地私有分支 rebase 到当前提交，跑它自己的测试，重新导出加密补丁，并提交 `private/mirror.patch.enc`。公开页面重做后补丁可能打不上，出包前一并调整。
4. 触发 `ios-unsigned.yaml`（`with_mirror` 按你的习惯），下载产物，用 `tool/mirror_patch.sh decrypt-ipa` 解密，把 `.ipa` 的本地路径交给你。
5. 你用 SideStore 装好后，按 §10.4 检查。

出包计划：M2 ①、M3 ②、M4 ③、M5 ④、M6 ⑤、M7 ⑥、M8 ⑦、M9 ⑧、M10 ⑨（0.4.0 正式）。你不想装某一期的话，告诉我跳过就行，下一期照样出。
